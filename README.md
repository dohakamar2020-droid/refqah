# رِفقة الأربعين

**رحلة علمٍ وحفظٍ وعمل** — مساحة تعليمية صغيرة لمتابعة دورة حفظ الأربعين النووية (42 حديثًا).

ليست مجرد جدول لتسجيل مَن حفظت ومَن سمّعت؛ الهدف أن تشعر الطالبات أنهنّ في رحلة علمية مشتركة، يرين تقدمهنّ، ويجدن تشجيعًا مستمرًا حتى تمام الرحلة.

## حسابات متعددة: كل معلمة بمساحتها

الموقع لم يعد لمعلمة واحدة. أصبح **متعدد المعلمات** على نفس قاعدة البيانات، مع فصل كامل:

| الحساب | كيف يدخل | ماذا يرى |
|---|---|---|
| **المعلمة** | «كود المعلمة + كلمة المرور» | طالباتها وأحاديثها وسجل تسميعها وتقاريرها وتكريمها فقط |
| **الطالبة** | «كود المعلمة + اسمها + كلمة المرور» (أو كودها الخاص `STU-…`) | ملفها الخاص فقط |

- **كود المعلمة** مثل `TCH-4K7T2M` — هو مفتاح المساحة، وهو نفسه كود انضمام طالباتها.
- **كود الطالبة** `STU-9Q2W5E` — يُولّده النظام عند إضافتها، وتسلّمه المعلمة لها.
- عند إنشاء أي معلمة جديدة تُنسخ لها نسخة مستقلة من الـ42 حديثًا ومكتبة الرسائل، وتفتح رحلتها بنفسها (لا شيء منشور بعد).
- تعديل حديث أو نشرُه أو اعتماد تسميعة عند معلمة **لا يمسّ** أي معلمة أخرى — التحقق من الملكية يجري على الخادم (`teacherId`) في كل قراءة وكتابة، وليس بإخفاء أزرار.
- صفحة فصل عامة لكل معلمة: `/c/TCH-XXXXXX` تعرض أحاديثها المنشورة وأفضل 3 من طالباتها الموافقات فقط.
- نظام اسم المستخدم/البريد + كلمة المرور القديم **باقٍ كطريقة دخول بديلة** (تبويب «اسم المستخدم» في صفحة الدخول)، وكل الحسابات القديمة تُنسب تلقائيًا لصاحبتها عند أول تشغيل.

**إضافة معلمة جديدة:** من `/register` تختار كودها واسمها وكلمة مرورها — أو أنشئي الأولى من `/setup`.

**انضمام طالبة بنفسها:** المعلمة تفتح «التسجيل الذاتي» من صفحة الطالبات، ثم تدخل الطالبة من `/join` بكود المعلمة واسمها وكلمة مرور تختارها؛ لا يمكن انتحال اسم موجود في الفصل، وكلمة المرور تحمي الحساب.

**للتطوير المحلي** لا تحتاجين Neon: إن لم يكن `DATABASE_URL` مضبوطًا، يستخدم المشروع **PGlite** (محرك Postgres حقيقي مجمّع إلى WebAssembly) داخل مجلد `.data/`، بنفس كود Drizzle وPostgreSQL تمامًا.

## التشغيل محليًا

```bash
npm install
cp .env.example .env.local     # أو استخدمي قيم التطوير الافتراضية
npm run seed                   # ينشئ الجداول + الأحاديث الـ42 + مكتبة الرسائل
npm run dev                    # http://localhost:3000
```

عند التشغيل محليًا تُضاف تلقائيًا 8 طالبات تجريبيات ويُنشر أول 12 حديثًا لتكون الواجهة قابلة للاستكشاف (لا يحدث هذا على Neon إلا بضبط `SEED_DEMO_STUDENTS=true`).

### أول تشغيل: شاشة الإعداد

**الموقع لا يأتي بأي كلمة مرور افتراضية.** في أول زيارة تظهر شاشة `/setup` وتطلب من المعلمة إنشاء حسابها (الاسم، اسم المستخدم، البريد، وكلمة مرور — ٨ أحرف على الأقل). بعد إنشاء الحساب تختفي شاشة الإعداد نهائيًا ولا تعود.

لتجهيز الحساب من سطر الأوامر بدل الشاشة (نشر آلي / CI):

```bash
SEED_ADMIN=true ADMIN_CODE=TCH-XXXXXX ADMIN_PASSWORD=<كلمة-مرور-قوية> npm run seed
```

### بيانات الدخول التجريبية

| الدور | كود الدخول | كلمة المرور |
|---|---|---|
| المعلمة | (تختارينه في شاشة الإعداد) | (تختارينها بنفسك) |
| طالبة تجريبية | معروض في صفحة الطالبات (`STU-…`) | `refqah2025` |

> لا توجد كلمة مرور افتراضية للمعلمة في أي بيئة — لا محليًا ولا على الإنتاج.

## النشر على Vercel + Neon

1. أنشئي قاعدة بيانات على [Neon](https://neon.com)، ثم اربطيها من **Vercel Marketplace** — تضيف Vercel متغير `DATABASE_URL` تلقائيًا.
2. أنشئي الجداول مرة واحدة:
   ```bash
   npm run db:push     # يستخدم drizzle/0000_init.sql
   # أو: npm run seed  (ينشئ الجداول ويملأ الأحاديث والرسائل)
   ```
3. اضبطي متغيرات البيئة في Vercel:
   ```
   DATABASE_URL=...              # من Neon
   BETTER_AUTH_SECRET=...        # سلسلة عشوائية طويلة
   BETTER_AUTH_URL=https://<your-domain>
   NEXT_PUBLIC_APP_URL=https://<your-domain>
   ```
4. أول حساب معلمة يُنشأ من شاشة `/setup` عند أول زيارة (كود + اسم + كلمة مرور). للنشر الآلي: `SEED_ADMIN=true ADMIN_CODE=… ADMIN_PASSWORD=…`.

## خريطة الصفحات

الموقع مقسوم إلى **ثلاث مساحات منفصلة تمامًا**، لا رابط بينها:

| المسار | الوصف | من يراه |
|---|---|---|
| `/` | الصفحة العامة: هوية الموقع ومعلومات الدورة، وبابان فقط: الطالبة والمعلمة. **لا تُعرض أي أسماء معلمات ولا أي بحث بالكود** | الزائرة (وتُحوَّل المسجّلة إلى مساحتها) |
| `/student/login` | دخول الطالبات — بكودها الخاص + اسمها + كلمة المرور | الطالبات |
| `/student` | **مساحة الطالبة**: الأحاديث المنشورة في فصلها فقط + نتيجة تسميعها + تصحيح معلمتها الذي تسجّله بنفسها | الطالبة صاحبة الحساب فقط |
| `/teacher/login` | دخول المعلمات — بكود المعلمة + كلمة المرور (مع تبويب اسم المستخدم القديم) | المعلمات فقط |
| `/register` | فتح مساحة معلمة جديدة (كود + اسم + كلمة مرور) | المعلمات الجدد |
| `/join` | انضمام طالبة بكود معلمتها (إن كان التسجيل مفتوحًا) | الطالبات |
| `/setup` | الإعداد الأول — إنشاء أول حساب معلمة (تظهر مرة واحدة) | الجميع، وتختفي بعد الإعداد |
| `/leaderboard` | أفضل 3 داخل فصلها بموافقتهنّ | الطالبة/المعلمة في نطاق فصلها فقط |
| `/admin` | لوحة المعلمة | المعلمة |
| `/admin/account` | حساب المعلمة: الاسم وكلمة المرور | المعلمة (حسابها هي) |
| `/admin/reports` | تقارير الطالبات — صورة جاهزة للمشاركة على واتساب | المعلمة |
| `/admin/recitations` | جدول التسميع لطالبات فصلها | المعلمة |
| `/admin/students` | طالباتها + **ترتيب الطالبات** + إرسال تصحيح تسميع على واتساب + إدارة كود الانضمام | المعلمة |
| `/admin/hadiths` | إضافة الأحاديث وتعديلها ونشرها | المعلمة |
| `/admin/honors` | **ألقاب الأحاديث**، التكريم، تشغيل/إيقاف المنافسة، مكتبة الرسائل | المعلمة |

## قواعد العمل الأساسية

- **حالتان فقط:** سمّعت / مسمّعتش.
- **الأحاديث غير المنشورة** لا تظهر للطالبة إطلاقًا: مساحتها تعرض المنشور فقط، وحتى لو حاولت طلب حديث غير منشور يرفض الخادم الطلب.
- **تصحيح المعلمة يصل على واتساب** (من صفحة الطالبات أو صفحة التقرير: تجهيز الرسالة وإرسالها)، ثم **تسجّله الطالبة بنفسها** في مساحتها (مواضع الأخطاء + ملاحظات) لتراجع عليه. السجل خاص بالطالبة وحدها، ولا يقرأه غيرها.
- **«سَابِقَةُ الخَيْرَات»** تُحسب تلقائيًا: أول تسميعة **معتمدة** للحديث الأول حسب وقت الاعتماد، وتُعاد حسابها عند أي تعديل أو حذف فتبقى صحيحة دائمًا.
- **المنافسة بنظام موافقة مزدوج:** الطالبة توافق من حسابها، والمعلمة تملك مفتاح التشغيل العام. لا تظهر إلا الموافقات، ولا يُعرض إلا اسم العرض وعدد الأحاديث.
- **التعادل** يُحسم لصالح مَن وصلت إلى العدد أولًا (أقدم وقت اعتماد).
- **ترتيب الطالبات بيد المعلمة**: من **لوحة المعلمة ← الطالبات ← ترتيب الفصل** تسحب المعلمة الأسماء (أو تستخدم الأسهم) فتُحفظ أرقام الترتيب فورًا، وهذا الترتيب هو نفسه في قائمة الطالبات وجدول التسميع والتقارير. الطالبة الجديدة تُضاف في آخر الترتيب، والطالبة التي لم تُرتَّب بعد تظهر في الآخر بترتيب الاسم.
- **ألقاب الأحاديث تتغيّر مع كل حديث**: من **لوحة المعلمة ← الألقاب والتكريم** تختار المعلمة الحديث، فيقترح النظام عليه ألقابًا مناسبة لموضوعه (`src/lib/data/titles.ts` — لكل حديث ٣ ألقاب + ألقاب عامة)، ولها أن تكتب لقبًا من عندها. اللقب يُمنح **للمركز الأول** في ذلك الحديث (طالبة واحدة لكل حديث، وتعديل اللقب يحدّثه ولا يكرّره). يظهر اللقب في مساحة الطالبة وتقريرها ورسالة الواتساب وصفحة التكريم، ويمكن سحبه في أي وقت.
- **رسائل التشجيع** تتغير تلقائيًا مع كل زيارة ولا تتكرر في زيارتين متتاليتين (تُستبعد الرسائل المعروضة سابقًا حتى تُستوفى المكتبة كلها). العبارات من صياغة أصلية للموقع، وليست أحاديث أو اقتباسات دينية منسوبة.

## تقرير الطالبة على واتساب

من **لوحة المعلمة ← التقارير** (أو زر «تقرير» بجانب أي طالبة) تفتح المعلمة تقريرًا مصمّمًا بنفس هوية الموقع — تدرّج الوردي الهادئ، زخارف نباتية، وخط أميري — يحتوي على:

- اسم الطالبة والتاريخ
- عدد الأحاديث التي سمّعتها من ٤٢، ونسبة التقدّم
- ثلاثة أرقام: سمّعت / لم تسمّع بعد / الأحاديث المنشورة
- آخر الأحاديث التي تم تسميعها
- الأوسمة (ومنها «سَابِقَةُ الخَيْرَات»)
- ألقاب الأحاديث التي حصلت عليها
- رسالة تشجيع

**طريقة الإرسال:**

- **على الجوال** — زر «مشاركة عبر واتساب» يفتح نافذة المشاركة مباشرة بالصورة مرفقة، وتختارين واتساب.
- **على الكمبيوتر** — يُنزَّل الصورة ويُفتح واتساب بالنص جاهزًا، وتضيفين الصورة بخطوة واحدة.
- يوجد كذلك «إرسال نص فقط» و«نسخ النص» لمن لا تريد صورة.

الصورة تُنشأ داخل المتصفح (html2canvas) حتى تظهر العربية بنفس شكل الخطوط المعتمدة. ولإظهار محادثة مباشرة، أضيفي رقم واتساب الطالبة بالصيغة الدولية (مثال `201012345678`) من صفحة الطالبات.

## الخصوصية والصلاحيات

| البيانات | المعلمة | الطالبة | الزوار |
|---|:--:|:--:|:--:|
| جميع أسماء الطالبات | ✔ | ✘ | ✘ |
| سجل التسميع الكامل | ✔ | ✘ | ✘ |
| سجلها الشخصي ونسبة تقدمها | ✔ | ✔ | ✘ |
| أفضل 3 (بالموافقة) | ✔ | ✔ | ✔ |

- **كل تحقّق يتم على الخادم** في كل عملية كتابة (`requireAdminOrThrow`)، وليس بمجرد إخفاء الأزرار.
- لا تستطيع طالبة تعديل حالة زميلتها ولا حتى حالتها، ولا الوصول إلى `/admin` (تُعاد للرئيسية).
- **لا يظهر عدد الطالبات ولا أي إحصائيات إجمالية عنهنّ في أي صفحة عامة.**
- لا يمكن تسجيل تسميع حديث غير منشور (يُرفض على الخادم).
- **الفصل بين المعلمات مُنفَّذ في الاستعلامات نفسها** (`where teacher_id = ?` في كل قراءة وكتابة)، فلا يمكن لمعلمة قراءة أو تعديل طالبة/حديث/تكريم معلمة أخرى حتى لو خمّنت المعرّفات.
- كلمة مرور الطالبة يحفظها Better Auth مجزَّأة (hash)، ولا تُعرض لأي أحد — لا للمعلمة ولا في التصدير.

### ملاحظة على نصوص الأحاديث

نصوص الأحاديث الـ42 مكتوبة في `src/lib/data/hadiths.ts` حسب ترتيب الإمام النووي، **منقولة حرفيًا وبالتشكيل الكامل** من نسخة المعلمة. كل حديث ثلاثة حقول منفصلة:

| الحقل | المحتوى | مثال |
|---|---|---|
| `narrator` | **الراوي** | «عن أميرِ المؤمنينَ أبي حفصٍ عُمَرَ بنِ الخطَّابِ رضيَ اللهُ عنه» |
| `arabicText` | **المتن** | «قالَ: سمعتُ رسولَ اللهِ ﷺ يقولُ: ((إنَّما الأعمالُ بالنِّيَّاتِ…))» |
| `takhrij` | **التخريج** | «رواه البخاريُّ ومسلم.» |

تُعرض الحقول الثلاثة في صفحة الأحاديث، ويمكن تعديل أيٍّ منها من **لوحة المعلمة ← الأحاديث**.

> أُعيد توليد مجلد `drizzle/` بالكامل في migration واحد (`0000_soft_thunderbolts.sql`)؛ لأن `0000_init.sql` القديم لم يكن مطابقًا للمخطط. يُطبَّق تلقائيًا محليًا، ويُنفَّذ مرة واحدة على Neon عند أول نشر.

## التطبيق القابل للتثبيت (PWA)

الموقع يعمل كتطبيق يُثبَّت على الجوال والكمبيوتر.

- **زرار التثبيت**: يظهر صغيرًا **أسفل يمين الشاشة من اليسار** (أسفل-شمال)، و**يختفي تلقائيًا** بعد التثبيت. لو الزائرة ضغطت × بيختفي كمان ومايرجعش.
  - على Chrome/Edge/Android: يفتح نافذة التثبيت مباشرة
  - على آيفون (Safari): يفتح شرح مصغّر «شارك ← إضافة إلى الشاشة الرئيسية» لأن سفاري ما بيوفّرش زر تثبيت برمجي
- **الملفات**: `public/manifest.webmanifest`، `public/sw.js`، `public/offline.html`، والأيقونات في `public/icons/`
- **الأيقونات تُولَّد** من نفس أشكال `LogoMark` في `src/components/floral.tsx`:

  ```bash
  python3 scripts/generate-icons.py
  ```

- **صفحة offline**: لما الانترنت يقطع، تظهر صفحة بنفس هوية الموقع بدل شاشة الخطأ

### تحديث نصوص الأحاديث على قاعدة بيانات موجودة

`src/lib/data/hadiths.ts` يحمل ثابت `HADITH_CONTENT_VERSION`. عند بدء التطبيق يقارن `seedHadiths()` هذا الرقم بالرقم المسجّل في جدول `site_meta`، فإن كان أحدث طبّق الراوي والمتن والتخريج الجديدة على الأحاديث الموجودة.

**لتعديل نص حديث:**

1. عدّليه في `src/lib/data/hadiths.ts`
2. ارفعي `HADITH_CONTENT_VERSION` بمقدار ١
3. انشري — عند أول طلب تُزامَن النصوص تلقائيًا

- الأحاديث اللي عدّلتها المعلمة من **لوحة الإدارة** تُعلَّم `textEdited` و**لا تُستبدل أبدًا**، ويظهر عليها وسم «معدَّل يدويًا».
- لإجبار مزامنة كاملة (تجاهل وسم التعديل اليدوي لا ينطبق — التعديلات تبقى محمية):

  ```bash
  FORCE_HADITH_SYNC=true npm run seed
  ```

### ⚠️ Service worker لا يخزّن صفحات HTML

كل صفحة في الموقع تُبنى على السيرفر حسب المستخدم، وفيها بيانات تسميع خاصة. تخزينها في الكاش معناه إن طالبة تقدر تشوف صفحة طالبة تانية على نفس الجهاز. فالـ service worker يخزّن **الأصول الثابتة فقط** (ـ`_next/static`، الأيقونات، الخطوط) و**لا يخزّن أي صفحة ولا أي استجابة `/api/`** — الخصوصية تفضل محكومة على السيرفر.
